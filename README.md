# AI Key Vault / ApiKeyHub

一个更适合自己长期用的 AI API Key 管理小工具。

它不是那种花里胡哨的大平台，核心思路就一件事：把手上的 Key、地址、模型先收整齐，再用最省事的方式判断它现在到底还能不能用、能看到哪些模型、哪个模型更适合拿来当默认模型。

如果你手里经常有多套 OpenAI 兼容渠道，或者总在不同平台之间来回复制 Key，这个项目基本就是为这种场景准备的。

## 现在已经支持什么

### 🔐 配置管理

- 在项目侧持久化多组配置，包含名称、Base URL、API Key、默认模型、API 格式、测试方式
- 配置写入项目目录 `data/configs.json`（由 `/api/configs` 原子读写），Docker 部署时可通过 volume 挂载保留
- 支持复制单条配置，也支持复制全部配置
- 支持导出 `.txt` 和 `.md`
- 配置列表支持搜索、筛选；还没测试过的新配置会排在列表最前，其余按最近测试时间排序

### 📥 导入解析

- 支持粘贴解析，能识别 `curl`、JSON、环境变量风格文本、结构化文本块、`ccswitch://` 链接
- 支持导入 `cc-switch` 导出的 `.sql` 文件，也支持直接粘贴 SQL 文本
- 支持一次粘贴多个配置，解析后可批量直接新增
- 支持把解析结果先回填到表单，再决定要不要保存

### ✅ 可用性测试

- 支持单条测试，也支持一键测试全部配置；批量测试为低并发错峰执行，避免并发齐射触发上游限流
- 可按配置选择 API 格式：自动兼容 / Chat Completions / Responses / Anthropic Messages
- 自动兼容会按 stream → chat → `/responses` 顺序尝试，并在需要时回退
- 每张卡片可切换「测试方式」，工具栏也提供一键全局切换（只影响当前所在列表）：
  - **仅测选中**：成功列表的默认方式，只测试配置/推荐的模型，失败即失败，不自动换模型
  - **循环测试**：失败列表的默认方式，默认把整份模型列表逐个测一遍，记录每个模型到底能不能用；开了「热点模型」则只测命中的那几个
- 循环测试按「同一供应商每 N 秒测一个模型」的节奏推进，默认 20 秒：顶部可设全局默认值，卡片上也能为单个供应商单独覆盖，站点有 RPM 限制时把间隔调大即可。还没做过模型识别的卡片会自动先补一次识别，保证扫的是整份列表而不是配置里那一个模型；单轮最多扫描 200 个模型，并会自动跳过画图、向量等非对话模型
- 卡片「状态」后面提供「测试列表」按钮，点开可看本轮每个模型的成功/失败、耗时与错误详情，支持按结果筛选、按模型名搜索、一键复制明细。列表以当前热点命中为准：刚勾上的热点如果已经能命中站点模型，会先以「未测」出现在列表里，不必等再跑一轮才看得见。弹窗默认只显示成功的模型，要看失败/未测时用顶部快速筛选切换。跑的过程中可随时「停止」，已出的结果照样保留；明细会随配置一起持久化，刷新页面后仍能看到
- 卡片折叠后按测试方式区分显示：循环测试的卡片只在名称旁边以绿色标签显示最近一次测试时间，选中模型、命中模型和结果详情不再占地方；仅测评中的卡片显示当前模型、实际命中模型与测试结果，不放测试时间

### 🔥 热点模型

- 配置列表顶端有「热点模型」按钮，点开按主力厂家分组勾选：OpenAI / Claude / DeepSeek / GLM / Gemini / Grok / Moonshot(Kimi) / MiniMax / Mimo / Qwen / 其他，每个分组内按版本号从新到旧排列
- 候选默认并到**大版本 + 一级小版本**：`glm-5.3-flash` 收成 `glm-5.3`、`deepseek-v4-flash-0731` 与 `deepseek-v4-pro` 收成一条 `deepseek-v4`、`gpt-5.1-mini` 收成 `gpt-5.1`、`claude-sonnet-4-5` 原样保留。`flash / pro / mini / thinking` 这类变体词和日期快照不再各占一格；要逐个挑变体时切到「完整型号」即可
- 折叠结果保证是原名的前缀，所以勾 `glm-5.3` 仍然能命中站点上的 `glm-5.3-flash`；`-0309`、`-32k`、`-8b` 这类日期/规格尾巴不会被误当成小版本。画图、向量、rerank、语音、娱乐套壳一类非对话/无用模型也不会出现在候选里
- **一条热点会测掉该站点上所有「真正不同」的变体**，不是只测一个。变体之间按指纹去重，但只有**真镜像**才算同一个模型：日期快照（`-0731`）、上下文长度标记（`-1M`）、`free / latest / beta / temp / stable` 这类别名后缀。反过来，凡是在站点上**各自独立上架**的名字都算不同模型，一律各测一次：`flash` 与 `pro`、`27b` 与 `flash`、`fast` 与 `think`、`mini`，以及思考档位 `-high / -medium / -low / -minimal`。之前把档位当成噪音，导致 `黑白公益-gemini` 的 `gemini-3.7-flash-high` 与 `-medium` 明明匹配上热点却永远测不到
- 不测的模型：画图 / 向量 / rerank / 审核 / 语音合成与转录（`-tts`、`whisper`），以及**娱乐套壳模型**——像 `只会喵喵叫/gpt-5.6-sol` 这种挂在恶搞前缀下、名字看着是真模型但只会喵喵叫的条目，既不进测试也不进热点候选，纯属白烧 token
- 开了热点模型后，如果这张卡片的模型列表是空的、或者识别结果已超过 7 天，循环测试会**先自动补一次模型识别**再开测。站点新上架的模型不在旧列表里，是「热点明明选了却测不到」的主要来源，而 `/models` 不消耗 token
- 「测试列表」弹窗会把**本站点没有的热点模型单独列出来**（标成「不占用测试次数」），循环测试的结论里也会显示「N 个热点本轮没测到」，不会出现选了却静默不测的情况
- 候选模型直接来自你各站点识别到的真实模型（外加测速过、配置过的名字），再补一份内置主力模型候选，避免站点还没识别过时没得选；也支持手动输入任意模型名
- 保存并开启「循环测试只测热点模型」后，每张卡片的循环测试只测这份列表在该站点命中的模型，不再整表扫描白烧 token。匹配对中转站命名做了归一化：忽略 `org/` 前缀、大小写、下划线、日期后缀，以及**连字符写法差异**，所以 `minimax-m3` 能命中 `minimaxai/minimax-m3`，`deepseek-v4-flash` 能命中 `deepseek-v4-flash-0731`，`qwen3.8` 也能命中写成 `qwen-3.8-flash` 的模型
- 勾选顺序即测试优先级；某站点一个热点模型都没命中时，退化为只测配置的那一个模型而不是扫全表；关掉开关随时回到全量扫描
- 候选列表里同一族的两种写法（`qwen3.8` 与 `qwen-3.8`）会合并成一个格子，不会重复占位也不会重复测
- 列表与开关保存在 `data/hot-models.json`（由 `/api/hot-models` 原子读写），换浏览器也不会丢
- **卡片前缀聚合折叠**：自动提取站点名称前缀（如 `黑白公益-def` / `黑白公益-gemini` / `黑白公益-glm` 聚成 `黑白公益` 组，`霸气公益-0元购` / `霸气公益-free` 聚成 `霸气公益` 组），在同一卡片盒中收纳展示并带成功/失败统计，支持一键整组展开/折叠，顶部提供「前缀聚合」开关随时切回平铺列表
- 卡片在两个列表之间迁移时会自动切换为所在列表的默认方式；同一列表内也可以单独覆盖某张卡片的设置
- 循环测试通过时，测试结果会记录并展示实际通过的模型，和配置的模型区分开
- 针对免费公益站的误判治理：放宽测试超时（流式 60s / 非流式 45s，流式带空闲看门狗）、把推理模型的思考内容也视为有效回复、限流/超时类瞬时错误自动延迟重试一次
- 测试结果会记录状态、实际命中模型、错误详情、最近测试时间

### 🧠 模型识别

- 支持读取当前 Key 在该渠道下能看到的模型列表
- 识别完成后会给出推荐模型，并支持复制模型列表；推荐时会自动跳过画图、向量等非对话模型
- 支持在识别结果里直接切换当前模型
- 模型列表与配置卡片支持按分类筛选：GPT / Claude / GLM / DeepSeek / Gemini / Grok / Mimo / Moonshot (Kimi) / MiniMax / Qwen 等。配置列表的筛选按「测试列表里测成功过的模型」判断：循环测试明细里成功过的模型，或仅测选中时上次测试成功的模型，属于哪个厂就在哪个分类出现；只配置了名字但没测通的不算，「全部」不受影响

### ⚡ 性能评测

- 支持按模型做 1 到 3 轮测速
- 会展示平均耗时、中位耗时、首字时间、成功率、稳定性
- 支持按模型名或 tag 搜索模型，方便从长列表里筛选
- 会自动汇总最快模型、首字最快模型、最稳模型，并给出一个默认推荐模型
- 会自动跳过明显不适合做对话测速的模型，比如 embedding、rerank、部分图像类模型

### 🔗 CC Switch 联动

- 支持导出到 CC Switch，也支持直接唤起 CC Switch 导入
- 当前已适配的目标 App 包括 `Claude`、`Codex`、`Gemini`、`OpenCode`、`OpenClaw`

### 🎨 界面与主题

- 支持浅色 / 深色 / 跟随系统
- 主题偏好保存在浏览器 `localStorage`，配置数据本身不依赖浏览器本地存储

- 手上有多套 AI API Key，想统一收纳的人
- 经常会忘记某个渠道地址、模型名、Key 放哪了的人

## 隐私和数据说明

配置数据默认保存在**项目部署目录**的 `data/configs.json` 中，由同源接口 `/api/configs` 读写。该文件包含 API Key，已被 `.gitignore` / `.dockerignore` 排除，请勿提交到 Git，也不要输出到日志。

热点模型列表保存在同目录的 `data/hot-models.json`，由 `/api/hot-models` 读写，不含密钥，只记录模型名与开关。

主题模式仍保存在浏览器 `localStorage`（键名 `ai-key-vault-theme-v1`）。

连通性测试、模型识别、性能评测会经过项目自己的同源后端代理转发，主要是为了绕开浏览器直连上游时的 CORS 限制。简单理解：

- 配置数据存在你自己部署的服务端文件里，不接外部数据库
- 真正发请求测试时，Key 会参与当前这次后端转发请求
- 请自行做好部署环境与 `data/` 目录的访问控制

## 快速开始

```bash
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000) 就能开始用。

首次运行会自动创建 `data/configs.json`；开发时该目录已预留 `.gitkeep`。

## 打包部署

```bash
npm run build
npm run start
```

部署到支持 Next.js 的平台也没问题，比如 Vercel、Netlify 等。若使用无状态托管平台，请注意 `data/configs.json` 可能无法跨实例持久化，此时建议改为挂载持久化存储，或自行扩展存储后端。

## Docker 一键部署

项目已经带好 `Dockerfile` 和 `docker-compose.yml`，本机装好 Docker 后，直接执行：

```bash
npm run docker:deploy
```

默认会自动构建镜像并在后台启动容器，然后访问 [http://localhost:3000](http://localhost:3000)。

`docker-compose.yml` 会把宿主机 `./data` 挂载到容器 `/app/data`，用于持久化配置文件。

常用命令：

```bash
npm run docker:logs
npm run docker:down
```

如果你不想走 `npm` 脚本，也可以直接用：

```bash
docker compose up -d --build
```

## 使用方式很简单

1. 填一条配置，或者直接把现成的 `curl` / JSON / 文本块粘进来
2. 按需选择 API 格式（默认自动兼容）
3. 点「保存配置」或者「粘贴并直接新增」
4. 先做连通性测试，确认地址和 Key 没问题
5. 再做模型识别，看看这个渠道到底开放了哪些模型
6. 如果模型很多，就打开性能评测，跑几轮后挑一个更适合日常使用的默认模型
